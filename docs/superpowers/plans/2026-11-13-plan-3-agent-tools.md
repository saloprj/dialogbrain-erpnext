# Plan 3 — Agent tools + DialogBrain changes, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The DialogBrain AI agent answers customers with live ERPNext data: catalogue, prices and stock for anyone; order status and unpaid invoices only for the verified customer of that chat. A manager's reply from ERPNext counts as a human reply (the agent pauses). Managers can take a chat over from the agent and give it back.

**Architecture:** Two parts, in two repos.

- **Part A — DialogBrain repo, one PR series.** Four small server changes:
  1. `/api/tools/{id}/execute` passes `request_id` and `api_key_id` into ToolContext.
  2. A per-thread agent pause tool usable with an API key.
  3. Signed thread-context headers on HTTP integration calls.
  4. An `agents.get_draft` tool returning the full draft text.
- **Part B — this app.**
  - Whitelisted `dialogbrain.agent_api.*` methods called by DialogBrain as an HTTP integration.
  - Thread-context signature verification.
  - Registration of that integration at Connect.
  - The take-over UI.
  - Sends that use `request_id`.
  - Full draft text.
- Part B detects each Part A capability from the tool catalogue and degrades gracefully when it is missing (spec §7.3).

**Tech Stack:** DialogBrain api-gateway (FastAPI, Python, plain-SQL migrations, pytest). Frappe/ERPNext v15+v16 app `dialogbrain` (Python 3.10, Vue 3 inbox).

**Thread-context contract (shared by A3 and B2)**

- Headers sent by DialogBrain on an HTTP integration call made inside an agent run that belongs to a thread, when the integration's `config.send_thread_context` is true:
  - `X-DialogBrain-Thread-Id: <internal thread id, decimal>`
  - `X-DialogBrain-Timestamp: <unix seconds>`
  - `X-DialogBrain-Context-Signature: sha256=<hex>`
- The signature is `HMAC-SHA256(key=secret_bytes, msg=f"{timestamp}.{thread_id}.{METHOD}.{path}")`, where:
  - `METHOD` is uppercase;
  - `path` is the URL path without the query string, exactly as sent;
  - `secret_bytes` is UTF-8 of the stored secret, a 64-hex-char string generated by ERPNext.
- The secret is stored in DialogBrain in `workspace_secrets` under `secret_ref_name("thread_ctx", integration_id)`, and in ERPNext in the Password field `thread_context_secret`.
- ERPNext accepts the call when the timestamp is within ±300 s and the signature matches (constant-time compare). The thread id is the DB Conversation `thread_id`, i.e. the internal id (Plan 1 R10).
- Calls with no context, a bad or expired signature, an unknown thread, or a conversation whose `link_source` is not `manual`/`auto_verified` get no customer data. They return `{"identified": false, "message": "customer not identified"}`.

**Agent API (Part B)**

- Methods live in `dialogbrain/agent_api.py`, all `@frappe.whitelist(methods=["POST"])`.
- They are callable only by the agent user (`Settings.erpnext_agent_user`) with the role `DialogBrain Agent API`. Any other session gets PermissionError.
- Every call writes a `DB Agent Call Log` row: `tool, thread_id, conversation, party_type, party, identified (Check), result_count (Int), error (Small Text)`. Keep rows for 30 days via a daily job.
- Output is compact JSON for an LLM: no internal ids beyond document names, and amounts rounded to the currency precision.
- Generic tools:
  - `get_item(query, limit=5)`: search `item_code`/`item_name`/`description` among enabled, sales Items. Returns `{item_code, item_name, price, currency, stock_qty, in_stock}`.
    - Price: the Item Price on the Selling Settings default price list.
    - Stock: the sum of `Bin.actual_qty` over the warehouses of the channel's company. With no thread context, use `Settings.default_company`.
  - `create_lead(name, phone=None, email=None, note=None)`: creates a Lead. If the call carries a valid context, also links it to the conversation when the conversation has no party (`link_source manual`) and sets the custom field `db_conversation`.
- Customer-scoped tools (identified via context only; no phone/email/customer argument is accepted):
  - `find_customer()`: `{identified, customer_name, party_type, outstanding_total[{currency, amount}]}`.
  - `order_status(order_no=None)`: the last 5 submitted Sales Orders of that customer, or the one named by `order_no` if it belongs to them. Fields: `name, date, status, delivery_date, per_delivered, per_billed, grand_total, currency`.
  - `unpaid_invoices()`: submitted Sales Invoices with outstanding > 0, max 10.
  - `create_draft_order(items=[{item_code, qty}])`: a Draft Sales Order for that customer, never submitted, with `db_conversation` set. It creates a Notification Log for the assigned manager, or for the channel's permitted users if unassigned.
- Write tools (`create_lead`, `create_draft_order`) are listed in `denied_tools` for every agent by default. The Settings checkbox `allow_agent_writes` removes them.

## Review Focus

1. **A forged, replayed or old thread-context header, or a context naming another workspace's or another chat's thread.** Expected: no customer data, and the call is logged as `identified=0`. Tests in B2 (ERPNext verify) and A3 (DialogBrain signs only for the run's own thread).
2. **A chat linked `auto_unverified`** (e.g. a phone typed into livechat). Expected: customer tools return "not identified", never that customer's orders. Test in B2.
3. **The LLM tries to pass `phone`/`customer`/`order_no` of someone else.** Expected: extra args are ignored or refused, and `order_no` returns nothing unless it belongs to the identified customer. Test in B2.
4. **The agent API is called by a desk user or Guest, or with the agent user's key from another site.** Expected: PermissionError. Test in B1.
5. **Connect against a DialogBrain without the Part A changes.** Expected: Connect succeeds; customer tools are not registered; take over, `request_id` and full drafts are hidden or skipped; Settings shows which capabilities are missing. Test in B3.
